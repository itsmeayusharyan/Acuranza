Haptic strength fixed for real: Light and Standard previously triggered the IDENTICAL vibration (a mapping bug in the old View-feedback path - three different code paths also disagreed with each other), so changing strength did nothing. Every interaction now vibrates through one shared VibrationEffect implementation: amplitude 36/128/255 (Light/Standard/Strong) on devices with amplitude control, otherwise distinct pulse lengths (14/30/55ms). The calculator keypad and segmented controls now respect the selected strength instead of a hardcoded weakest-effect buzz. Test feedback previews the exact same path the app uses and says so plainly if the device has no vibrator. Vibrations respect the system haptic setting and never stack on rapid taps.
